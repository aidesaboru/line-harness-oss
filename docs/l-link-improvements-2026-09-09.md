# 会話記録から抽出したLリンク改善

会話記録のうち、Lリンクへ直接関係する改善は次の2件です。中国案件、営業体制、採用、ショップレビューなど、Lリンクの機能変更ではない話題は対象外です。

## 1. 営業が顧客状況を確認できる専用画面

### 困っていたこと

- 営業やアポインターが、バックオフィスでクレーム対応中か分からない
- 状況を知らずに追加提案や連絡を行い、顧客体験を悪化させる恐れがある
- 毎回運営スタッフへ聞かないと判断できない
- 会話本文まで営業へ見せる必要はない

### 必要な状態

- 営業責任者、営業担当、アポインターがいつでも顧客状況を見られる
- 一覧で顧客と現在の状態を確認できる
- 顧客を開くと、現在の営業アクションと過去の状態履歴が分かる
- 営業閲覧アカウントは、この専用画面以外へアクセスできない
- 会話本文、サポート内部メモ、配信、設定などは営業へ公開しない
- 状態は運営側が更新し、過去のクレームと解決経緯を上書きせず残す

### 実装した状態

| 状態 | 営業側の判断 |
|---|---|
| 確認前 | 運営へ確認してから連絡 |
| 通常運用 | 通常対応可 |
| 要注意 | 運営確認後に連絡 |
| クレーム対応中 | 営業連絡を止める |
| 退会手続き中 | 営業連絡を止める |
| 退会済み | 連絡対象外 |

新しい `/sales-customers` 画面には、リスク件数、検索、状態絞り込み、リスク優先一覧、顧客詳細、営業共有メモ、更新履歴があります。個別LINEだけでなく、既存の顧客情報を持つグループLINEとルームLINEも対象です。

スタッフ管理では「営業閲覧（顧客状況のみ）」を選べます。このアカウントはAPI側でも許可先を限定し、顧客状況の読み取り、自分のログイン状態、在席更新以外を拒否します。状態更新はowner、admin、通常のstaffだけが行えます。

## 2. 二次対応からの差し戻しと再提出

### 困っていたこと

- 二次対応者が差し戻しても、一次対応者が気づけない可能性がある
- 一次対応者が差し戻し理由を確認し、情報を補って再提出する導線がない
- 差し戻しが二次対応側の未回答件数へ残り続ける

### 実装した状態

- 差し戻し理由を必須化
- 一次対応者と案件作成者へLリンク内通知とWeb Pushを作成
- 案件を「一次対応待ち」へ移動
- 一次対応者が差し戻し理由を見て、追加情報を入力し、二次対応へ再提出
- 元の依頼、差し戻し理由、追加情報をつないだ新しい依頼を作成
- 元の差し戻しと回答は履歴として保持
- 共有閲覧者や二次対応者による再提出を拒否

詳細な操作は [サポートCRM運用マニュアル](./manual/ec-owner-support-crm.md) に記載しています。

## 反映状況

両改善ともローカル実装と自動テストの対象です。この文書作成時点では、新しい顧客状況画面を本番反映済みとは扱いません。本番反映は、バックアップ、ビルド、画面確認、デプロイ承認を別に確認します。

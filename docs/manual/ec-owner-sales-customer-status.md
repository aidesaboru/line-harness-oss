# 営業向け顧客状況 運用マニュアル

## 目的

営業連絡や追加提案の前に、クレーム、要注意、退会手続きの有無を確認し、不適切なタイミングでの連絡を防ぎます。

この画面は会話本文を見る場所ではありません。運営側が営業へ共有してよい要点だけを短く記録します。

## 営業・アポインターの使い方

1. 管理者から「営業閲覧（顧客状況のみ）」のAPIキーを受け取る
2. Lリンクへログインする
3. 自動で「顧客状況」画面が開く
4. 連絡予定の会社名、担当者名、顧客番号を検索する
5. 状態と「営業アクション」を確認する
6. 「要注意」「クレーム対応中」「退会手続き中」「確認前」の場合は、画面の指示どおり運営へ確認する

営業閲覧アカウントでは、個別チャット、サポートCRM、顧客管理、配信、設定などは表示されません。URLを直接開いても利用できません。

## 状態の判断基準

| 状態 | 判断基準 | 営業アクション |
|---|---|---|
| 確認前 | 運営がまだ状態を判定していない | 運営へ確認 |
| 通常運用 | 営業連絡を止める要因が現在ない | 通常対応可 |
| 要注意 | 不満や調整中の事項があり、内容・時期の確認が必要 | 運営確認後に連絡 |
| クレーム対応中 | 契約、品質、対応などへの強い不満を運営が対応中 | 営業連絡を止める |
| 退会手続き中 | 退会・解約の申し出があり、確認や手続き中 | 営業連絡を止める |
| 退会済み | 退会・解約手続きが完了 | 連絡対象外 |

不満の強さだけで迷う場合は、まず「要注意」にして運営確認を求めます。営業連絡を止める必要があると判断した時点で「クレーム対応中」にします。

## 運営スタッフの更新方法

1. 「顧客状況」を開く
2. 対象顧客を検索して開く
3. 「運営側の状況更新」で状態を選ぶ
4. 「営業共有メモ」に、営業が次の行動を判断するための要点を書く
5. 「状況とメモを保存」を押す

営業共有メモの例:

- `契約内容の認識差を確認中。解決連絡があるまで追加提案は停止。`
- `対応完了を双方で確認済み。通常の案内を再開してよい。`
- `9月末で退会手続き中。更新・アップセルの連絡は行わない。`

書かないもの:

- LINE会話本文のコピー
- 電話番号、住所、支払情報など、営業判断に不要な個人情報
- サポート内部だけで扱う感情的な表現や未確認情報
- APIキー、外部サービスの認証情報

保存するたびに、変更前の状態、変更後の状態、共有メモ、更新者、日時が履歴へ追加されます。過去履歴は上書き・削除しません。

## 日次運用

- 営業は顧客へ連絡する直前に確認する
- 運営はクレーム受付、退会希望、解決確認のタイミングで状態を更新する
- 朝会では「要確認」「クレーム」「退会手続き中」の件数を見る
- 「確認前」を通常運用とみなさない
- 解決時は「通常運用」または「退会済み」へ更新し、再開・停止の判断を共有メモに残す

## 管理者による営業閲覧アカウントの作成

1. ownerで「スタッフ管理」を開く
2. 「スタッフを追加」を押す
3. 名前を入力する
4. ロールで「営業閲覧（顧客状況のみ）」を選ぶ
5. 発行されたAPIキーを本人へ安全に渡す

営業閲覧アカウントを通常の一次対応へ変更すると、顧客状況以外の一次対応機能も利用できるようになります。変更前に対象者と必要権限を確認してください。
